# DSH Desktop 实施路线图

## 目的

本路线图把《DSH Desktop Windows 客户端设计》拆成四个能够独立评审和验收的
实施阶段。每个阶段使用独立详细计划，前一阶段的公开接口和验证结果是后一阶段的
输入，避免在一个超长变更中同时处理进程、更新、皮肤和安装器风险。

## 阶段顺序

### 阶段 1：桌面壳与受管进程基础

详细计划：
`docs/superpowers/plans/2026-08-21-dsh-desktop-phase-1-foundation.md`

交付一个可启动的 Tauri 2 Windows 桌面壳。它具备单实例、启动页、类型化状态、
动态回环端口、受管子进程、探活、主 WebView 导航、托盘隐藏/恢复和安全退出。
该阶段使用仓库内的模拟 DSH 服务验证完整生命周期，不下载真实运行时。

退出条件：

- TypeScript 和 Rust 单元测试通过；
- 模拟服务能够从启动页切换到 WebView 页面；
- 关闭窗口隐藏到托盘，托盘退出回收模拟服务进程树；
- Windows 10/11 x64 开发构建可以启动；
- 没有远程页面可调用的通用 shell 或文件系统权限。

### 阶段 2：兼容运行时、首次安装与更新

单独计划覆盖签名运行时清单、Node 24 LTS 与官方 DSH 运行包制作、HTTPS 下载、
摘要与签名校验、版本目录、数据副本探活、首次安装、版本发现、通知、切换和回滚。
该阶段把阶段 1 的 `RuntimeLaunchSpec` 从模拟服务替换为实际兼容运行时。

退出条件：

- 全新用户目录可下载并启动固定兼容版 DSH；
- 断网、签名错误、摘要错误、磁盘不足均不改变当前版本；
- 官方新版与兼容新版通知分离且去重；
- 更新在数据副本上探活后切换，首次失败恢复旧版本；
- 已运行任务期间不会切换运行时。

### 阶段 3：沉浸皮肤与设置体验

单独计划覆盖原生图片选择、格式与上限校验、只读资源协议、皮肤设置窗口、CSS
适配器、实时预览、版本适配检查和失败降级。正式鲸鱼图标集在该阶段接入窗口、
托盘、通知和设置页。

退出条件：

- PNG/JPG/JPEG/WebP 选择、复制、恢复默认和设置持久化可用；
- 背景层支持填充、位置、模糊、遮罩和面板透明度；
- 官方业务请求和状态不被皮肤层拦截；
- 未验证页面结构自动回退到官方界面；
- 4K/8K 背景不在滚动时重复解码。

### 阶段 4：安装器、卸载器与发布硬化

单独计划覆盖 NSIS 当前用户安装、WebView2 Bootstrapper、快捷方式、默认保留数据
的卸载行为、日志脱敏与滚动、性能测量、Windows 10/11 测试矩阵、签名桌面更新
清单和小范围测试发布流程。

退出条件：

- `setup.exe` 无需管理员权限即可安装；
- WebView2 缺失设备能够通过 Evergreen Bootstrapper 补装；
- 默认卸载移除桌面版 DSH 但保留用户数据，删除数据必须二次确认；
- 冷启动、空闲 CPU、内存和皮肤开销有可复现测量记录；
- 安装、覆盖安装、保留数据重装和回滚烟雾测试通过。

## 跨阶段固定约束

- 仅支持 Windows 10/11 x64。
- 桌面端不 fork、不修改官方 DSH 包。
- DSH 只监听 `127.0.0.1`，动态端口不作为身份验证手段。
- 主窗口长期只保留一个 WebView2 和一份 DSH 实例。
- `%APPDATA%\DSH Desktop` 保存用户数据，`%LOCALAPPDATA%\DSH Desktop`
  保存可重新下载的运行时与缓存。
- 不读取或修改现有 `~/.dsh` 和全局 DSH。
- 新增生产依赖必须先取得用户确认并提交锁文件。
- 删除旧版本、快照、皮肤或用户数据必须由用户明确触发并确认。
- 每个阶段使用 TDD、类型化公共接口、结构化错误、脱敏日志和频繁小提交。
