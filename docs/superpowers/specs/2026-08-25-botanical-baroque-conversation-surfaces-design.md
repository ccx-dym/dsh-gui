# 植物系巴洛克对话表面设计

## 背景

当前沉浸式皮肤为输入卡片和用户消息气泡复用同一组半透明背景、边框与阴影。两者虽然共享“对话表面透明度”，但视觉职责不同：输入卡片是持续交互的操作区域，用户消息气泡是已经发送的历史内容。相同样式使历史气泡看起来像缩小的输入框，也缺少用户期望的装饰性。

本次改动为两类表面提供固定的 C×H“植物系巴洛克”样式。C 风格提供藤蔓、叶片和少量花朵，H 风格提供浅金描边、卷草与点珠。样式不分析壁纸、不提取人物，也不调用本地或云端模型。

## 目标

- 输入卡片使用完整的植物系巴洛克边框装饰。
- 用户消息气泡使用同一视觉语言的精简装饰，保持方向性和紧凑度。
- 输入卡片与气泡继续共享现有“对话表面透明度”，但分别维护背景、边框、圆角、阴影和装饰声明。
- 装饰在不同窗口宽度、长短消息和多行输入下不遮挡文字或控件。
- 装饰不接收鼠标事件，不影响输入、选择、复制及按钮点击。
- 只在已经通过版本门禁的沉浸式皮肤页面中生效，并沿用现有失败关闭与清理流程。

## 非目标

- 不识别壁纸颜色、人物、主体或场景类别。
- 不生成或存储透明人物图、蒙版、调色板或派生图片。
- 不新增皮肤设置、样式选择器或独立透明度滑块。
- 不修改背景图协议、设置 Schema、持久化迁移或外观设置页。
- 不引入动画、网络请求、云端服务或生产依赖。
- 不扩大适配器支持的 DSH 版本、来源或 DOM 合约。
- 不装饰助手回复、系统注入记录、审批、菜单、弹窗或危险确认表面。

## 方案选择

采用内嵌 SVG 与 CSS 伪元素实现固定装饰。输入卡片和用户消息气泡继续由当前稳定语义选择器定位：

- `[data-composer-card]`；
- `[data-chat-flow-kind="user"] [data-slot="conversation.message.images"] + div`。

每个表面使用 `::before` 承载不参与布局的装饰图层，原元素继续承载玻璃背景、边框和阴影。不动态插入装饰 DOM，避免监听 React 重渲染或为每条消息维护节点生命周期；不使用 PNG/WebP 边框，避免缩放模糊和扩展本地资源协议。

装饰不会把一张完整 SVG 拉伸到任意宽高。角花、中央卷草和点珠拆成多个小型 SVG 数据 URI，通过同一伪元素的多重 `background-image`、`background-position`、`background-size` 和 `background-repeat: no-repeat` 独立定位。

## 视觉规范

### 固定色板

装饰使用固定、低饱和色板，不从壁纸动态取色：

- 藤蔓与叶片：薄荷绿；
- 花朵与点珠：柔和粉色；
- 外框与卷草：浅金色；
- 边缘光：低透明度暖金色。

颜色只用于边缘装饰，不作为正文底色。玻璃底色继续根据既有浅色或深色遮罩设置生成，并使用现有 `conversation_surface_opacity_percent` 控制不透明度，从而保持不同壁纸上的基本可读性。

### 输入卡片

输入卡片使用完整版装饰：

- 保留深色或浅色玻璃底，并使用浅金色细外框；
- 左上放置薄荷绿藤蔓和一朵粉色小花；
- 顶部中央放置无文字的小型浅金卷草；
- 右下放置与左上呼应的反向藤蔓；
- 底边中段放置低密度粉色点珠；
- 使用弱金色边缘光与现有玻璃阴影，不增加持续动画。

输入卡片装饰不得覆盖占位文字、编辑区、附件入口、模式按钮、工作区选择器、模型选择器和发送按钮。装饰图层只绘制边缘区域，中心保持透明。

### 用户消息气泡

用户消息气泡使用精简装饰：

- 保留与输入卡片一致的玻璃色系和浅金色细边框；
- 右上使用短藤蔓与单朵小花；
- 左下使用短卷草；
- 不使用顶部中央徽饰或完整底边点珠；
- 圆角保持右下收角，继续表达消息发送方向；
- 阴影弱于输入卡片，避免历史消息获得过强悬浮层级。

短消息、长消息和自动换行都只改变气泡主体尺寸，角部 SVG 保持固定视觉尺寸，不随气泡宽度横向拉伸。

## CSS 层级与交互

两个目标元素设置明确的定位上下文和隔离层级。玻璃底、真实边框与阴影由元素本身绘制；`::before` 使用绝对定位覆盖元素边界，并设置：

- `content: ""`；
- `position: absolute`；
- `inset` 为受控的小范围边缘偏移；
- `pointer-events: none`；
- 多重内嵌 SVG 背景；
- 不透明中心区域保持为空。

伪元素作为第一个绘制子层，业务内容继续显示在其后。SVG 只包含固定路径和固定颜色，不包含脚本、外部链接、字体、用户文本或远程资源。表面不通过 `overflow: hidden` 裁剪装饰；所有越界范围保持在小幅、固定的安全区内，避免侵入相邻消息或滚动条。

装饰不改变元素尺寸、内边距或消息布局，也不创建新的焦点目标和可访问性节点。因为本次没有动画，不需要新增 `prefers-reduced-motion` 分支。

## 响应式降级

当对话工作区变窄时，装饰按固定优先级降级：

1. 隐藏输入卡片顶部中央卷草；
2. 隐藏输入卡片底边点珠；
3. 保留输入卡片左上和右下角花；
4. 用户消息气泡始终只保留精简角部装饰。

降级通过媒体查询完成，不读取窗口尺寸、不注册 JavaScript 监听器。输入卡片多行扩展时，角花锚定四角，中央卷草和点珠只沿对应边缘定位，不随高度拉伸。

## 适配器结构

`src-tauri/src/skin/adapter.rs` 继续生成唯一的桌面皮肤 `<style>`。当前合并的对话表面字符串拆分为职责明确的私有生成单元：

- 共享玻璃色与不透明度数据；
- 输入卡片基础表面声明；
- 用户消息气泡基础表面声明；
- 输入卡片装饰声明；
- 用户消息气泡装饰声明；
- 窄窗口降级声明。

内嵌 SVG 使用编译期固定常量，CSS 生成函数只插入已经验证的数值颜色和透明度，不接受用户提供的 SVG、路径或任意字符串。公共 API、适配器版本标识和页面报告协议保持不变。

现有清理脚本继续移除整个 `dsh-desktop-skin-style` 节点，因此关闭沉浸模式、切换到不兼容页面或适配失败时，基础表面与伪元素装饰会同时撤销，不需要额外清理节点。

## 兼容与失败回退

- 只对当前精确版本适配器已经验证的两个语义选择器应用样式。
- 页面来源、版本签名或 DOM 合约不兼容时，不注入装饰并沿用现有官方界面。
- 浏览器无法解析某个 SVG 数据 URI 时，只丢失该装饰图层；真实边框、玻璃底和业务交互仍然可用。
- SVG 无脚本、无外链且不访问文件系统，不扩大远程 DSH 页面的原生能力。
- 浅色和深色遮罩继续决定玻璃底的基础 RGB；固定装饰色不修改主题变量、文字颜色或焦点样式。

## 测试策略

实现遵循 Red-Green-Refactor，先用失败测试锁定生成 CSS 的稳定行为。

### Rust 适配器测试

- 输入卡片与用户消息气泡不再共享一段完全相同的完整声明。
- 生成 CSS 包含两个目标选择器各自的 `::before` 装饰规则。
- 装饰规则包含内嵌 SVG 数据 URI、`pointer-events: none` 和禁止平铺的声明。
- 输入卡片包含藤蔓、花朵、中央卷草和点珠图层；气泡只包含精简角部图层。
- 媒体查询会隐藏中央卷草与点珠，同时保留角花。
- 用户选择的对话表面透明度仍同时作用于两个基础表面。
- 浅色与深色遮罩都生成合法表面颜色，固定 SVG 内容不随用户输入变化。
- `glass_blur_px = 0` 与正值路径都包含相同固定装饰，但继续遵守各自既有玻璃滤镜行为。
- 清理脚本、来源门禁、版本门禁、唯一背景层和 DOM 兼容报告继续回归。

- 短消息、长消息、连续多条用户消息和包含图片的用户消息；
- 空输入、单行输入和多行输入；
- 输入聚焦、选择文字、复制、附件入口、模式切换、模型选择和发送；
- 正常窗口、窄窗口和 Windows 缩放比例场景；
- 开关沉浸式皮肤、重新导航和不兼容适配器回退。

## 验收标准

1. 输入卡片显示完整植物系巴洛克装饰，用户消息气泡显示同系精简装饰，两者不再像同一组件的大小版本。
2. 所有装饰均为固定内嵌 SVG/CSS，不读取壁纸、不调用模型、不访问网络。
3. 装饰不覆盖正文、输入内容或任何控件，不改变布局尺寸，不拦截鼠标事件。
4. 长短消息、多行输入和窄窗口下没有拉伸失真、重叠或横向溢出；窄窗口按约定隐藏次要装饰。
5. 对话表面透明度、浅深遮罩和毛玻璃强度继续按现有设置工作。
6. 关闭皮肤、页面不受信、版本不兼容或 DOM 合约失败时完整恢复官方样式。
7. 不新增设置字段、持久化迁移、生产依赖、网络权限或外部服务配置。
