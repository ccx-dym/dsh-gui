# 主窗口全域沉浸式皮肤设计

## 背景

当前 DSH `0.1.1-rc.2` 的皮肤适配器已经把图片绘制到主页面 `body`，但主窗口仍有两处明显的非沉浸区域：Windows 原生标题栏不能显示 WebView 背景，左侧栏继续使用 `--dsw-specific-sidebar-fill` 的实色表面。同时，对话输入卡片通过 `--dsw-specific-input-major` 绘制不透明背景。

本次改动只作用于主聊天窗口。外观设置窗口与更新窗口继续使用 Windows 原生标题栏。现有皮肤设置字段、图片协议、版本兼容门禁、更新链路与托盘退出语义均保持不变。

## 目标

- 皮肤图片从主窗口左上角连续覆盖到右下角，包括自绘标题栏、左侧栏和对话内容区。
- 普通对话与首页居中态的输入卡片背景透明，同时保留可读的文字、边框和操作按钮。
- 主窗口保留拖动、双击最大化、最小化、最大化/还原、关闭到托盘等桌面窗口行为。
- 皮肤关闭、图片无效或 DSH 适配失败时，主窗口仍有可操作的标题栏和稳定的主题回退。
- 外观设置窗口与更新窗口的窗口装饰和行为不变。

## 非目标

- 不把所有按钮、弹窗、菜单或危险确认表面设为完全透明。
- 不改变皮肤设置模型或新增用户可配置项。
- 不为外观设置窗口和更新窗口实现自绘标题栏。
- 不扩大官方 DSH 页面对更新、文件、皮肤设置或其他原生命令的权限。
- 不支持未经精确验证的 DSH 版本或 DOM 合约。

## 方案选择

采用“主 WebView 内自绘标题栏”方案：仅关闭 `main` 的系统装饰，由桌面壳在主页面每次加载完成后注入固定标题栏。背景仍由同一个主 WebView 的 `body` 绘制，因此标题栏和业务内容共享一张连续图片。

未采用独立标题栏 WebView，因为两个 WebView 的背景缩放、DPI 与窗口尺寸需要额外同步，难以保证图片无缝衔接。保留原生标题栏只能改变系统颜色，不能显示皮肤图片，不满足目标。

## 窗口架构

### 窗口配置

仅将 `tauri.conf.json` 中标签为 `main` 的窗口设置为无系统装饰。`updates` 与 `appearance` 不设置该选项，继续使用当前原生标题栏。

主窗口保持现有宽高、最小尺寸与可调整大小设置。Windows 无边框窗口的调整大小行为必须在 release 实际程序中验证，包括正常窗口、最大化窗口以及 100% 和 125% 缩放。

### 标题栏注入

桌面壳新增单一标题栏脚本生成器，并在主 WebView 的每次 `PageLoad::Finished` 后执行。该路径同时覆盖：

- 内置本地启动页；
- 导航完成后的官方数字回环 DSH 页面。

标题栏使用固定且由桌面壳拥有的 DOM ID。注入前先移除旧节点，确保同一页面最多存在一个标题栏。导航开始时旧页面自然失效；完成后重新建立当前页面的事件处理。

标题栏高度固定为 31px，包含：

- 左侧应用图标与 `DSH Desktop` 文本；
- 中间可拖动区域；
- 右侧最小化、最大化/还原、关闭按钮；
- 最大化状态对应的可访问按钮名称和图形状态。

标题栏使用固定定位并处于业务浮层之上。页面内容从标题栏下方开始，但 `body` 背景仍覆盖完整视口，使图片延伸到标题栏下方。标题栏不绘制独立实色背景；按钮仅在悬停、键盘聚焦和按下时显示轻微半透明反馈。

### 窗口控制命令

新增类型化窗口动作枚举，只允许以下动作：

- `start_dragging`；
- `minimize`；
- `toggle_maximize`；
- `close`。

公共 Tauri 命令必须具有完整类型注解和 Sphinx 风格中文 Docstring。命令接收调用方 `WebviewWindow` 与封闭动作枚举，并在执行前校验：

- 窗口标签严格等于 `main`；
- 来源是内置本地启动页，或当前允许的数字回环 DSH 页面；
- 动作属于封闭枚举。

命令只改变调用方主窗口状态，不读取或返回路径、皮肤设置、运行时状态等数据。`close` 调用窗口关闭流程，由现有 `CloseRequested` 处理继续决定隐藏主窗口或隐藏到托盘，不绕过现有退出语义。

窗口动作使用独立 capability 和自动生成权限文件。官方 DSH 来源只获得这一项窄权限以及现有皮肤适配报告权限，不获得通用窗口 API。

## 皮肤渲染

### 全视口背景

现有 `body` 背景继续作为唯一可靠画布，复用当前图片协议 URL、填充方式、位置、遮罩与模糊设置。不得创建第二张标题栏专用图片，也不得独立计算标题栏背景位置。

无模糊时，`body` 直接绘制遮罩和图片；有模糊时，现有 `body::before` 叠层继续覆盖完整视口。标题栏、侧栏和内容根节点均位于背景层之上。

### 透明表面

适配器在现有 `:root,#root` 主题覆盖中增加：

- `--dsw-specific-sidebar-fill: transparent !important`，移除主侧栏实色填充；
- 保持 `--dsw-alias-bg-base: transparent !important`，使主布局和对话根继续透出背景。

输入卡片不通过全局覆盖 `--dsw-specific-input-major` 实现透明，因为该变量还被附件、审批与其他需要可读底色的表面复用。适配器只针对已验证 DOM 合约中的 `[data-composer-card]` 设置 `background: transparent !important`。该稳定属性同时覆盖首页居中输入卡片和普通会话底部输入卡片。

输入卡片继续保留边框、文字、光标、按钮和必要阴影。`layer-1`、`layer-2`、弹窗、菜单、审批以及危险确认等表面继续使用当前“面板透明度”计算出的 RGBA 颜色，避免交互界面失去边界和可读性。

### 无皮肤回退

标题栏注入独立于沉浸式皮肤适配器。下列任一情况发生时，只撤销桌面壳拥有的皮肤节点和样式，不移除标题栏：

- 用户关闭沉浸式皮肤；
- 图片摘要无效或图片加载失败；
- 当前 runtime 版本或签名兼容结论不满足门禁；
- DSH DOM 合约检查失败。

无皮肤时，本地启动页或 DSH 页面自身的主题背景覆盖完整无边框窗口，标题栏文字和按钮使用当前主题可读色。窗口控制始终可用。

## 生命周期与状态

主页面加载开始时，现有皮肤页面令牌继续失效。页面加载完成后的顺序为：

1. 注入或刷新标题栏，使无边框窗口先恢复基本控制能力；
2. 根据当前 runtime、来源和皮肤设置应用皮肤或固定清理脚本；
3. DSH DOM 合约就绪后报告皮肤兼容结果。

标题栏脚本不得依赖 DSH 主题变量已经挂载；它使用带回退值的颜色，并在主题变量出现后自然继承。皮肤脚本仍执行现有的有限帧只读重试，不能用无限定时器或观察整个业务 DOM。

标题栏按钮状态在点击或窗口尺寸变化后从原生窗口状态更新。事件处理必须去重，不能在重复注入或同页刷新后累积监听器。

## 安全与错误处理

- 动态皮肤值仍只来自封闭枚举、整数边界和规范 SHA-256 摘要。
- 标题栏 DOM、样式、动作名称和可见文案全部由桌面壳静态生成，不拼接 DSH 页面数据。
- 官方 DSH 页面仅能调用封闭的主窗口动作命令；命令再次执行窗口标签与来源校验。
- 不使用裸 `except`，不向页面或日志写入底层 Tauri 错误正文、URL、用户路径或皮肤设置。
- 标题栏注入或窗口动作失败只记录固定诊断阶段和固定错误类别，不影响 runtime supervisor、更新或皮肤持久化。
- 皮肤适配失败继续失败关闭到官方主题，但不得使无边框主窗口失去关闭或移动能力。

## 测试策略

实现遵循 Red-Green-Refactor，每项生产改动前先运行能捕获对应缺陷的失败测试。

### 原生窗口测试

- 静态验证只有 `main` 配置为无系统装饰，`updates` 与 `appearance` 保持原生装饰。
- 验证窗口动作枚举只接受四个允许动作。
- 验证非 `main` 窗口、非可信来源和未知动作均失败关闭。
- 验证关闭动作进入现有关闭事件路径，不直接退出进程。
- 验证 capability 只把新命令授予本地主窗口和官方数字回环主页面。

### 可执行脚本测试

使用 Node DOM harness 执行真实生成脚本，验证：

- 标题栏包含应用标识、三个窗口按钮、可拖动区域和可访问名称；
- 重复执行脚本后标题栏仍只有一个，监听器不会累积；
- 拖动、双击和三个按钮映射到正确的类型化动作；
- 旧页面或异常 DOM 不会抛出未处理错误；
- 皮肤脚本包含透明侧栏变量和 `[data-composer-card]` 精确透明规则；
- 皮肤关闭或清理脚本不会移除标题栏。

### 回归与实际验证

运行以下完整验证：

- Rust 格式化检查；
- 相关 Rust 定向测试与完整 `cargo test --locked`；
- `cargo clippy --locked --all-targets -- -D warnings`；
- `pnpm test`；
- `pnpm build`；
- 安全 fixture smoke；
- release 构建和 Windows 实际程序视觉检查。

实际程序必须覆盖：启动页、DSH 首页、普通会话、皮肤关闭、皮肤开启、最小化、拖动、双击最大化、最大化/还原、关闭到托盘，以及 100% 和 125% Windows 缩放。

## 验收标准

1. 皮肤图片从主窗口左上角连续覆盖到右下角，标题栏不再是独立实色区域。
2. 左侧栏不再显示整块实色背景，且导航文字和交互仍可读。
3. 首页和普通会话的输入卡片背景透明，边框、文字与操作按钮仍清晰。
4. 标题栏支持拖动、双击最大化、最小化、最大化/还原和关闭到托盘。
5. 最大化后内容不被标题栏遮挡，窗口边缘不溢出屏幕；100% 和 125% 缩放均可正常使用。
6. 皮肤不可用时主窗口回退到当前主题，标题栏和窗口控制保持可见可用。
7. 外观设置窗口与更新窗口继续使用 Windows 原生标题栏。
8. 未扩大官方 DSH 页面除主窗口控制与既有皮肤报告之外的权限。
